# Erdős–Straus 猜想试跑任务

这个目录是一个给 **Long-Run Captain** 试跑用的数学任务种子。

## 任务

> 尝试证明或证伪 Erdős–Straus 猜想：
> 对任意整数 n > 1，方程
>
> ```
> 4/n = 1/x + 1/y + 1/z
> ```
>
> 都有正整数解 x, y, z。

## 建议成功标准（v2：不允许“失败即报告”直接完成）

1. 对 n ≤ 2000 完成暴力验证，并把脚本和结果作为证据。
2. 完成文献调研：已知结果、已知证明思路、当前开放状态，来源可核验。
3. 尝试至少 2 个不同证明/构造方向；每个方向必须给出精确阻塞点。
4. 只要没有证明或证伪，就必须继续 replan：换方向、修 gap、拓宽思路。
5. 只有 `budget.maxRounds` 用尽后，才允许产出“强部分结果 + 精确阻塞点 + 下一步建议”的报告。

注意：不要把“如果不能证明就写报告”放进初始成功标准。那会让 mission 过早完成。
如果你确实只想要一次有界调研，用：

```text
termination_policy: budget-or-success
budget: { maxRounds: 8 }
```

## 可复用文件

- `verify_erdos_straus.py` — CPU 友好的暴力验证脚本。
- `verified_2000.txt` — n ≤ 2000 的验证结果。

## 在 DSH 里启动

在 Long-Run Captain 会话中粘贴：

```text
启动一个 mission：尝试证明或证伪 Erdős–Straus 猜想。
termination_policy: success
budget: { maxRounds: 12, maxHours: 16 }
成功标准：
- 给出 Erdős–Straus 猜想的完整证明，或给出反例并严格验证
- 对 n <= 2000 完成暴力验证，并把脚本和结果作为证据
- 完成文献调研，记录已知结果与证明思路
- 尝试至少 2 个不同证明/构造方向，记录精确阻塞点
```

如果预算用尽仍未解决，主持人会先暂停/汇报，不会自动把“部分结果”当作完成。

## 注意

- 这是一个开放问题，不要期望一定证明完成。
- 对 CPU 很轻：暴力验证到 n ≤ 2000 只需要几十秒。
- 正好适合测试 Long-Run Captain 的：大量联网调研、失败后 replan、苏格拉底自查、独立评审、最终审计。
